Why is the status bar sitting over my comic?

You are reading a vertical-scroll comic on an iPhone, and the clock, battery and signal are drawn on top of the artwork the entire time. There is no setting for it. Here is why, everything that does not work, and the one thing that does.

Can you hide the status bar while reading in a comics app on iPhone?

In most of them, no. The clock, battery and signal are drawn on top of the page for the entire reading session, and there is no setting that removes them — not in the reader app and not in iOS. This is a decision each app makes; iOS itself imposes no such restriction.

Does the Tapas iOS app have a fullscreen or immersive reading mode?

As of August 2026, no. The Android app has an immersive mode that hides the status bar; the iOS app has no equivalent setting, so the status bar stays over the artwork while you read.

This is an observation, not an announcement — apps change, and if a version ships with the setting then this page is out of date and the setting is the better answer.

Is this an Apple restriction? Why can Android apps do it and iPhone apps cannot?

It is not an Apple restriction. iOS has given every app the ability to hide the status bar for years, through the public prefersStatusBarHidden property. WEBTOON's iOS app hides it while reading using that same public API. Nothing about the platform prevents it — the change simply has not been made.

Does adding the site to the Home Screen as a web app hide the status bar?

No. This is the workaround most often suggested and it does not work. The apple-mobile-web-app-status-bar-style meta tag set to black-translucent only lets page content pass underneath the status bar. The clock and battery still draw on top of it.

Can the Fullscreen API make Safari fullscreen on iPhone?

No. requestFullscreen is not supported on iPhone Safari outside of video elements. On iPad it works; on iPhone it does not, so no website or bookmarklet can put itself full screen.

Does Guided Access hide the status bar?

No. Guided Access hides the home indicator at the bottom of the screen and locks you into one app. The status bar at the top stays exactly where it was.

What about rotating to landscape?

The status bar does go away in landscape on iPhone. But portrait is the correct aspect ratio for a vertical-scroll comic — landscape trades the problem for a worse one.

What actually does hide it?

A native app. A view controller returning true from prefersStatusBarHidden hides the status bar in both portrait and landscape, using documented UIKit API with no orientation spoofing. That single override is the entire difference, and it is why the fix has to be an app rather than a setting, an extension or a website.

What is SlimRead?

A small open-source iOS web browser, built around that one override. You sign in to the site you already use and read it in the browser, except that nothing is drawn over the page. It also scrolls continuously from one chapter into the next instead of stopping at a wall of comments.

It is a browser, not a client for any service: it hosts no content, stores nothing offline, bypasses no paywall, and is not affiliated with any company. Every page and image is loaded live from the site's own servers over your own logged-in session, exactly as a browser would. Subscriptions, purchases and creator payouts all happen on the site, under its terms.

How hard is it to install?

On Windows it is two steps: download the repository as a ZIP, extract it, and double-click one file. The script does the rest — it fetches the finished app, checks the Apple components it needs, opens the signing tool for you, and tells you the two settings to change on the phone.

There is no Xcode, no command line, no building, no GitHub account, no paid developer account and no money involved. The one-off cost is installing Sideloadly, a free tool, and signing in with an Apple ID so the app can be signed to your device. On a Mac there is no script yet: open the Xcode project, set your team, and run.

If something does go wrong, the script stops and explains itself rather than closing, and the README has a troubleshooting entry for every failure seen so far.

Do I need a jailbreak to use it?

No. It is installed by sideloading, which is signing the app with your own Apple ID on your own device. A free Apple ID works; apps signed with one stop opening after seven days and need re-signing, and the project documents several free ways to automate that.

Why is it not on the App Store?

App Review rejects apps that are largely a wrapper around a website, and an app whose reason for existing is presenting somebody else's site differently would not survive that review. Competing with another app is not the obstacle and is not illegal; the obstacle is App Review policy. So it is distributed as source code that you build and sign yourself.

How do you hide the status bar in a WKWebView browser in Swift?

Override prefersStatusBarHidden to return true on the view controller, set UIViewControllerBasedStatusBarAppearance to true in Info.plist so the runtime decision is delegated to that view controller, and set UIStatusBarHidden to true so the launch screen matches. Override prefersHomeIndicatorAutoHidden and preferredScreenEdgesDeferringSystemGestures to remove the home indicator as well. All of it is public API and App Store compliant.

override var prefersStatusBarHidden: Bool { true }
override var preferredStatusBarUpdateAnimation: UIStatusBarAnimation { .fade }
override var prefersHomeIndicatorAutoHidden: Bool { true }
override var preferredScreenEdgesDeferringSystemGestures: UIRectEdge { [.top, .bottom] }

Why this exists at all

The unauthorised copies of this work are, today, easier and more pleasant to read than the paid original — better layout, nothing covering the art, no friction. SlimRead exists because one reader would rather patch around a single unmet request than switch sides. The lesson for anyone shipping a reading product: when the paid, legal path is worse than the free, illegal one, you teach your own audience to leave.
